# V2.2 · iPhone hotfix · 18/09/2026

## Reported failure

After V2.2 publication, the user supplied three physical-iPhone Safari screenshots: garden labels and the host note overlap; the daily note is dense; opening music leaves only the scenery. This supersedes the earlier Chromium viewport smoke as evidence for physical Safari acceptance. That earlier smoke did not catch the failure.

## Changes

- New last-loaded `garden-mobile.css`: mobile music dialog gets definite top/height from visualViewport, rather than auto height around a100% child. Playlist becomes an absolute sheet inside that sized dialog, with one scroll body and a fixed transport footer.
- Mobile dialog/sheet no longer depends on opacity/transform entrance animation. Music geometry is assigned before `showModal()`. `pageshow` refreshes hidden state and viewport measurements; visualViewport scroll/resize updates both offset and height.
- Remove duplicate large scenic text labels on phones; actual object hotspots and persistent three-item navigation remain. Compact host note gets its own lane above navigation, or above the measured mini-player when present. Main navigation, note and mini-player no longer share the same area.
- Daily note gets bounded scroll height, smaller margins and stronger text color.
- New cache keys: `app.js?v=22-iphone1`, `garden-mobile.css?v=22-iphone1`. No song data, original art, audio source or playback control replacement.

The indefinite-height chain and nested viewport-fixed sheet are confirmed implementation risks. The precise rendering trigger on this user's Safari build was not directly reproduced: native Safari inspection failed to start screen capture. Do not claim physical-iPhone success until the user retests. WebKit's top-layer explanation is at https://webkit.org/blog/12209/introducing-the-dialog-element/ ; browser bug reports are background context, not proof of this exact cause.
