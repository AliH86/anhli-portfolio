# V2.1 · Album dropdown direction

Latest user correction: “nó vẫn xổ dọc ra … playlist nào từng cục vậy đâu”; “research thêm kiểu xổ menu game”. This supersedes the earlier horizontal tile experiment. The final runtime uses one continuous vertical playlist, each song a horizontal row.

References inspected on 17 September 2026:

- [Unity uGUI dropdown](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/script-Dropdown.html): a trigger expands a list, selection updates the current value, the list collapses, overflow scrolls. Used as interaction reference only; no Unity dependency.
- [GDQuest crafting list](https://www.gdquest.com/tutorial/godot/design-patterns/mediator/): one coherent panel with consecutive rows, left-side markers and clear selection. Used as list hierarchy reference only; no inventory feature.
- [Kenney UI Pack](https://kenney.nl/assets/ui-pack): panel/button/state asset language. No Kenney asset was downloaded or included.

Applied to the existing garden: moss-green panel, warm cream type, brick selected row, small ink numbers, subtle playing indicator, a label with chevron. The menu opens from the album controls, scrolls vertically, closes after selecting a song or clicking elsewhere, and supports Up/Down/Home/End; Escape closes the menu before the music room. Existing native HTML buttons keep keyboard semantics. No grid of song cards, horizontal song rail, neon HUD, ornate fantasy border, scores or game mechanics.

Desktop: 320px menu below the sleeve, separate from the transport panel, leaving the host clear. Portrait: the sleeve/host stage stays fixed; the dropdown and transport scroll within the lower deck. The album shelf remains horizontal because it browses separate albums, not songs.
