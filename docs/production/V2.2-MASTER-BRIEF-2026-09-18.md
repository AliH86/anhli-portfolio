VƯỜN CỦA LI — V2.2
MASTER UI / ART / UX / TECHNICAL OVERHAUL BRIEF

Context
-------
V2.1 hiện đã có một base world rất tốt:
- background garden / cottage / music stall / photo board / lake / character
- overall art direction
- content architecture
- 3 main destinations:
  1. Sạp nhạc
  2. Chuyện của Li
  3. Điều để dành

"portfolio có giao diện game"

thành:

"một khu vườn/game-world cá nhân, trong đó portfolio là những thứ người dùng khám phá."

1. restore build/content pipeline

==================================================
3. HONEST UI FALLBACK FOR UNPLAYABLE CONTENT
==================================================

Even after fixing the root cause, make the UI resilient.

If an album genuinely has no playable audio:

Do not show it exactly like a playable album.

Instead use the new V2.2 art system to show something like:

"Đang cập nhật"

rather than a normal "8 BÀI" badge.

The treatment must integrate naturally into the wooden/vine/record-store design.

For disabled Play controls:

Do not expose only:

aria-label="Phát nhạc"
disabled

Use an accessible explanation such as:

"Album này chưa có file nhạc."

or equivalent semantic description.

Users and screen readers must know WHY playback is unavailable.

5. SẠP NHẠC — MAJOR REDESIGN
==================================================

Sạp nhạc is the hero interaction of the site.

Current weakness:
when opened, the environment still contains a beautiful record stall,
but the actual music UI appears as generic cards floating over it.

Treat the stall as a GAME LOCATION.

Opening Sạp nhạc should feel like entering/using the stall.

Do not need a huge cinematic sequence yet.

First establish structural logic:

STALL
→ physical record shelf/display
→ album browsing
→ album selected
→ record/player
→ listening state


DESKTOP / LAPTOP

We have significant screen real estate.

The album shelf should become much larger and more emotionally important.

Design a proper horizontal album CAROUSEL / DISPLAY SHELF.

Target behavior:

- selected album is visually dominant
- neighboring albums remain visible
- selected item gently scales forward
- side albums recede slightly
- magnetic/snap behavior
- smooth inertial movement
- clear previous/next navigation
- wheel/trackpad-friendly
- drag/swipe support where appropriate
- album focus should feel tactile

Possible structure:

[ album ][ album ][ SELECTED ALBUM ][ album ][ album ]

Each cover may sit inside a thematic frame:

wooden frame
+ restrained vines
+ flowers/foliage at corners
+ small label/tag

Do not cover album artwork excessively.

The shelf should visually CONNECT TO THE MUSIC STALL,
not feel like an independent slider library.


ALBUM SELECTION

When selected:

album becomes focus
vinyl / album art / information / controls gain prominence.

Avoid displaying:

album card
+ player card
+ playlist card
+ album strip

as four competing rectangles.

Use clear application states.

Suggested state machine:

BROWSE
→ SELECT
→ ALBUM
→ PLAYING
→ TRACKLIST

Opening deeper information should transform/reconfigure existing UI,
not continuously stack additional cards.

7. PLAYLIST — DESKTOP + MOBILE DIFFERENTLY
==================================================

Desktop:

Playlist can open as a ledger/drawer/record list connected visually
to the music stall/player.

Avoid generic floating cream panel.

Mobile currently has a serious UX issue.

QA at 390×844:

clicking ⋯ opens the playlist around:

y ≈ 799

Only ~45 px remains visible.

The parent tray does NOT automatically scroll to it.

There is also nested scrolling:
playlist scroll inside another scrolling tray.

When scrolling down to tracks,
transport controls disappear.


MOBILE V2.2 recommendation:

Use a dedicated BOTTOM SHEET for playlist.

Preferred structure:

-----------------------
drag handle
album / current track
-----------------------
track list
scrollable
-----------------------
sticky playback controls
sticky progress
-----------------------

Avoid nested vertical scrolling if possible.

Requirements:

- playlist becomes immediately visible when opened
- no manual scroll required just to find it
- progress/play controls remain reachable
- safe-area support for iOS
- Safari viewport height handling
- keyboard / orientation robustness
- smooth sheet open/close
- usable with touch

If keeping the current tray temporarily:
at minimum auto-scroll playlist into view.

But bottom-sheet architecture is preferred for V2.2.

13. WORLD MOTION
==================================================

Current wind/tree motion is too subtle or visually incoherent,
so users barely perceive it.

Do NOT solve this by moving everything more.

Natural motion requires DIFFERENT layers and DIFFERENT timing.

Examples:

large tree:
slow low-frequency sway

small leaves:
small faster flutter

flowers:
shorter flexible movement

grass:
localized ripple

hanging signs:
small pendulum motion

awning:
very subtle fabric response

water:
independent shimmer

butterfly:
irregular path

bird:
idle → hop → look → leave

Important:
avoid identical looping animation on all vegetation.

Use phase offsets / varied duration / amplitude.


==================================================
14. REAL TIME + WEATHER ARCHITECTURE
==================================================

Yes, the garden may eventually respond to:

local time
sunrise/sunset
weather conditions
possibly temperature/cloud/rain/wind

But weather MUST NOT block the core page.

Design the world-state architecture now even if full integration happens later.

Suggested world state concept:

world.timePhase
= dawn | morning | noon | afternoon | sunset | night

world.weather
= clear | cloudy | rain | storm | mist

world.wind
= calm | breeze | windy

The page should always have graceful fallback values.

TIME can work without external APIs using local browser time.

WEATHER may later use a weather service,
with privacy-conscious/coarse location or user-selected city.

Never require precise location merely to make the site usable.

Potential visual reactions:

clear:
normal garden

cloudy:
softer light

rain:
wet surfaces / rain overlay / umbrella/awning details

windy:
increased foliage movement

sunset:
warm light

night:
lanterns
window lights
fireflies
darker lake/sky

IMPORTANT:
do not implement full weather simulation before the core V2.2 art/UI system is stable.

Build hooks / architecture first.

21. PERFORMANCE RULES
==================================================

This is still a website.

Do not turn decorative UI into hundreds of giant PNGs unnecessarily.

Prefer:

CSS
SVG
small optimized WebP/AVIF assets
sprites where sensible
reusable textures

Respect:

prefers-reduced-motion

Do not run expensive animation loops when:
- tab hidden
- element offscreen
- user enables reduced motion
